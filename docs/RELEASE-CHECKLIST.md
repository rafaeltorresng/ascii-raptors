# Publication checklist

Before changing repository visibility:

- [ ] Review the prepared commits and confirm the approved visual output is intact.
- [ ] Confirm the repository is private, independent and contains only the intended branch/history.
- [ ] Confirm command-line validation passes from a clean checkout and GitHub Actions passes on Node 22 and 24.
- [ ] Review README, provenance, MIT license, retained regression media and known limitations.
- [ ] Confirm no secrets, local paths, generated output or archived experiments entered any commit.
- [ ] Obtain the owner's approval before making the repository public.

Tags, GitHub releases, npm publication, Pages and portfolio integration are separate actions. None is implied by preparing or pushing the private repository.

Current gaps to disclose, rather than claim complete: physical iOS/Android testing; full validation of the current shared scene in Gecko/Safari; assistive-reader review; independent anatomical review. Existing automated accessibility checks do not certify all contrast, motion or reader behavior. See `VALIDATION.md`.
